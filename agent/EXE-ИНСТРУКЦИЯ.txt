ГОТОВЫЙ КЛИЕНТ БЕЗ УСТАНОВКИ PYTHON

Скопируйте только MonitorClient.exe из папки dist в отдельную доступную
для записи папку на Windows Server, например C:\MonitorClient.
Дважды нажмите C:\MonitorClient\MonitorClient.exe.
На первом запуске появится мастер: адрес backend, токен, папка и службы.
После сохранения рядом создаётся config.yaml. Он содержит токен:
не передавайте его другим людям и не размещайте в общей сетевой папке.
На следующих запусках exe использует сохранённые настройки.
После сохранения настроек рядом с EXE также появляется TOKEN.txt.
В нём только настроенный токен, который можно скопировать целиком.
При запуске клиента (в том числе службы) файл обновляется из config.yaml.
Новый токен не генерируется: при первом подключении нужен SECRET_KEY
сервера Monitor. Без настройки клиента действительный токен неизвестен.
TOKEN.txt хранит секрет открытым текстом. Защищайте его так же, как config.yaml.
Если папка недоступна для записи, клиент продолжает работу и пишет
предупреждение; старый TOKEN.txt может быть неактуален.

Изменить настройки: запустите C:\MonitorClient\MonitorClient.exe --configure
(или добавьте --configure в поле «Объект» отдельного ярлыка).
Закрытие мастера без сохранения отменяет запуск.
Установить фоновую Windows-службу (от имени администратора):
  Сначала сохраните настройки через MonitorClient.exe --configure,
  затем завершите запущенный консольный клиент (Ctrl+C).
  MonitorClient.exe install
  MonitorClient.exe start
Проверить/остановить службу:
  MonitorClient.exe status
  MonitorClient.exe stop
Удалить службу:
  MonitorClient.exe remove
После `start` окно клиента держать открытым не нужно: Windows запустит
его автоматически после перезагрузки. Установка и управление службой
требуют консоли «Запуск от имени администратора».
После install запуск настроен автоматически; start запускает службу сейчас.
Не перемещайте и не удаляйте EXE после установки службы.
Обновление EXE: stop -> заменить EXE -> start.
Изменение настроек: stop -> --configure -> Ctrl+C -> start.
Удаление: stop -> remove.
Лог: agent-service.log рядом с EXE (до 4 файлов по 5 MiB).

Служба запускается от LocalSystem, а не от вашего пользователя.
Сетевые диски пользователя не видны. Для UNC-папок потребуется отдельная
служебная учётная запись с правами доступа (настраивается в services.msc).
Размещайте EXE и config.yaml в папке, куда могут писать только
администраторы и SYSTEM: иначе подмена EXE позволит повысить привилегии.
Проверьте права папки до установки. Не используйте общую папку Downloads.

Python, pip, Node.js и интернет для установки библиотек на клиенте не нужны.
Нужна связь с backend Monitor. EXE не настраивает firewall/HTTPS автоматически.
127.0.0.1 подходит только если backend работает на этом же компьютере.

EXE собирается под Windows x64. Совместимость со старым Windows Server
нужно проверять отдельно; ориентир — Server 2016 и новее.
Файл не подписан цифровой подписью: SmartScreen/антивирус может показать
предупреждение. Не отключайте защиту; проверяйте происхождение файла.
One-file EXE распаковывает встроенные библиотеки во временную папку при
запуске; это не установка Python в систему.

Для разработчика: BUILD-EXE.cmd пересобирает exe с Python 3.13.
Пользователю Windows Server этот сборочный файл не нужен.
