КАК ЗАПУСТИТЬ КЛИЕНТ НА WINDOWS SERVER

1. Скопируйте папку D:\Projects\monitor\agent с компьютера Monitor
   на Windows Server, например в C:\MonitorClient.
   Не копируйте .venv и config.yaml.
   Папку checks и остальные файлы оставьте вместе.

2. Установите Python 3.13 с Python Launcher (py).
   Node.js на клиенте НЕ нужен.

3. Дважды нажмите C:\MonitorClient\CONFIGURE.cmd.
   Это главный файл для ПЕРВОГО запуска и изменения настроек.
   Он установит зависимости, откроет мастер и запустит клиент.

4. В мастере укажите:
   - доступный с этого сервера адрес backend Monitor;
   - токен: значение SECRET_KEY из D:\Projects\monitor\backend\.env
     на компьютере, где работает Monitor;
   - локальную папку сертификатов на Windows Server;
   - системные имена служб через запятую, например W32Time, Spooler.
   Имя службы можно посмотреть в services.msc:
   свойства службы -> Имя службы (не Отображаемое имя).

5. Нажмите «Сохранить и запустить». Не закрывайте окно клиента.
   После успешного отчёта сервер автоматически появится в Monitor.
   Службы из watchlist.txt дополнительно отображаются на странице
   «Службы» сервера Monitor: карточки со статусом, история и алерты.

СЛЕДУЮЩИЙ ЗАПУСК: C:\MonitorClient\start-client.cmd
ИЗМЕНИТЬ НАСТРОЙКИ: C:\MonitorClient\CONFIGURE.cmd
ОСТАНОВИТЬ: Ctrl+C в окне клиента.

ВАЖНО ПРО АДРЕС:
127.0.0.1 всегда означает компьютер, на котором запущен клиент.
Для другого компьютера нужен сетевой адрес backend, а не 127.0.0.1.
 start-windows.ps1 запускает backend на всех интерфейсах (0.0.0.0, порт 80) —
 для удалённых клиентов откройте порт 80 в firewall сервера.
 Не открывайте текущий API в интернет без дополнительной защиты.

 start-windows.ps1 в корне проекта запускает СЕРВЕР И ДАШБОРД,
 а не клиент. На наблюдаемом Windows Server он не нужен.

Клиент пока работает в открытом окне: эти файлы не устанавливают
его как фоновую Windows-службу и не включают автозапуск.
Не передавайте посторонним config.yaml: в нём хранится токен.
